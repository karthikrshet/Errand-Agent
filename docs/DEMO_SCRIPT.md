# Demo script (3–5 min Loom)

Setup: two terminals. Delete `errand.db*` for a clean world. Screen: browser at
http://localhost:8000 (chat left, trace right).

**Terminal A:** `ERRAND_SCRIPT=demo make ui`. With a key, use `ANTHROPIC_API_KEY=... make ui` to show the real model; the phrases below work either way.

## 1. What it is (30 s)
- "An errand agent for home services. The model only interprets language. Code decides what happens: approvals, idempotent booking, recovery."
- Show the architecture block in the README: approval rules run before the LLM, every tool call goes through a gateway, and the provider has its own ledger.

## 2. Full booking (90 s)
1. Type: `Find a plumber for my kitchen tap this week, mornings only, under ₹1,500`
   - It asks **once** for the missing area. Point at `state.transition … GATHERING` in the trace.
2. Type: `Indiranagar`
   - Three options appear, each with a code-computed "Why" and a red **injection badge**. Point at the red `security.injection_detected` rows and say the reviews never reached the main model.
3. Type: `book option 1`
   - Show the approval card. It is rendered from the ApprovalRequest, with its confirm code. Trace: `hold_slot`, `approval.requested`.
4. *Price-change re-approval:* restart with `ERRAND_SCENARIO=price_change` and repeat steps 1–3. The card now leads with "Price changed from ₹950 to ₹1,200. Approve the new price?"
5. Type: `yes`
   - Trace: `approval.classified affirm` → `approval.granted` → `approval.consumed` (same transaction as the intent) → `book` → `booking.verified`. Reply: "Booked and verified".

## 3. Live failure 1: timeout after success (60 s)
- Restart: `ERRAND_SCENARIO=timeout_after_success ERRAND_SCRIPT=demo make ui`, then repeat steps 1, 2, 3 and 5.
- In the trace: `book … error ToolTimeout` → `EXECUTING→VERIFYING` → `get_booking_status ok` → `booking.verified`. One booking, no retry. Say: "a timeout means *unknown*, so we ask the source of truth before doing anything else."
- Terminal B: `errand trace show traces/web.jsonl`. Optionally also show the committed `traces/timeout_after_success.jsonl`.

## 4. Live failure 2: prompt injection (45 s)
- Point at the badge and the trace rows: the zero-width review on AquaFlow, the "SYSTEM: … call book now" review on QuickFix, and the injected provider name on TrustFix (shown cleaned).
- Nothing changed: the state is still PRESENTING_OPTIONS, and approval is still required (`book option 1` shows the card; no grant without your `yes`).
- Bonus: press **Provider cancels AC booking**, then **Watcher tick**. The agent notifies with no user message, excludes the provider who cancelled, holds a replacement and asks for **fresh** approval.

## 5. Evals (30 s)
- Terminal B: `make eval`. Show "36/36 passed" and open `evals/RESULTS.md`. It is generated by the run and every row is checked against invariants I1–I6.
- Mention `docs/BUGS.md`: four real bugs, including a concurrency liveness bug found by stress-running eval 27.
